# Модуль анализа бизнес-процессов

Статус: первый локальный прототип реализован; мультимодальный анализ пока не реализован.

## Цель

Научить SA-Copilot фиксировать наблюдаемые пользовательские сценарии, сравнивать варианты прохождения процесса и готовить основу для дополнительных проверок.

Модуль не заменяет аналитика и не объявляет гипотезы подтверждёнными бизнес-правилами.

## Реализовано в первом прототипе

- Создание сценария через веб-интерфейс.
- Проверка структуры и статусов входных параметров.
- Локальное хранение сценариев в `data/scenarios.json`.
- Сравнение выбранных сценариев относительно первого выбранного.
- Разделение подтверждённых изменений и неподтверждённых/отсутствующих значений.
- Сравнение результатов расчёта.
- Формирование плана дополнительных экспериментов, в том числе с изменением одного параметра за раз.
- API: `GET /api/scenarios`, `POST /api/scenarios`, `POST /api/scenarios/compare`.

Папка `data/` исключена из Git: пользовательские сценарии остаются локальными и не должны случайно попасть в репозиторий.

## Границы текущей версии

Пока не реализованы:
- загрузка и распознавание скриншотов;
- извлечение кадров и анализ видео;
- автоматическое исследование веб-форм;
- автоматическое заполнение действий и реакций системы по материалам;
- генерация инструкции на основе сохранённых сценариев.

Не подключаются корпоративные источники и рабочие системы. Сценарии вводятся вручную в тестовом интерфейсе.

## Принципы достоверности

1. Наблюдение должно ссылаться на источник: файл/видео и временную отметку либо номер кадра/скриншота. В текущей версии такие ссылки пока можно фиксировать в тексте наблюдений вручную.
2. Факт интерфейса отделяется от интерпретации его назначения.
3. Гипотеза не становится бизнес-правилом без подтверждения.
4. Если одновременно изменилось несколько параметров, нельзя приписывать изменение результата одному параметру.
5. Для каждого параметра фиксируется статус: `observed`, `hypothesis`, `confirmed_by_analyst`, `unknown`.
6. Неизвестные значения не заполняются догадками.
7. Итоговые выводы и инструкции — только черновики для проверки человеком.

## Модель данных сценария

```json
{
  "scenario_id": "SC-001",
  "process_name": "Расчёт условий перевозки",
  "input_parameters": [
    {
      "name": "region_from",
      "value": "Регион А",
      "status": "observed"
    }
  ],
  "user_actions": [],
  "system_responses": [],
  "calculation_result": {
    "value": "Ввоз разрешён",
    "status": "observed"
  },
  "observations": [],
  "hypotheses": [],
  "open_questions": [],
  "verification_status": "not_verified"
}
```

## Сравнение сценариев

Первый выбранный сценарий используется как базовый. Для каждого следующего сценария модуль:
- определяет изменившиеся параметры, если оба значения имеют статус `observed` или `confirmed_by_analyst`;
- отдельно показывает отсутствующие и неподтверждённые значения;
- сравнивает результат расчёта только при наличии подтверждённых значений;
- предупреждает о множественных одновременных изменениях;
- не делает вывод о причинно-следственной связи.

## Дополнительные эксперименты

Если изменилось несколько параметров, модуль предлагает отдельный эксперимент для каждого параметра: взять базовый сценарий, изменить только один выбранный параметр, остальные записанные параметры оставить на базовом уровне и повторить расчёт. Это план проверки, а не гарантия причинности: неучтённые параметры и состояние системы тоже могут влиять на результат.

## Запуск

Из корня проекта:

```powershell
py app.py
```

Открой в браузере: `http://127.0.0.1:8000`.

Сценарии сохраняются локально в `data/scenarios.json`. Для запуска не нужны платные API или корпоративные подключения.

## Тесты

Из корня проекта:

```powershell
py -m unittest discover -s tests -v
```

В набор добавлены тесты сравнения сценариев, локального хранилища и генерации предложений экспериментов. После запуска тестов локально результаты необходимо проверить в своей среде.
